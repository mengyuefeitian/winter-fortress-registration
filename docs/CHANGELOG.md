## v1.17.0（区管控制台去分区 / 盟管审核按分区隔离 / 兵种阶级同步）

### 区管控制台（`pages/admin/home`）
- **「当前分区」整块移除**（不只是对超管隐藏）：区管/超管进入都不再显示分区，切换分区统一在首页。
  页面仍在后台加载 `selectedZone`，因为「清空数据 / 联盟活跃 / 盟管审核」需要 zoneId，只是不再渲染。

### 盟管审核（`pages/superAdmin/admin-review`）
- **区管控制台进入时只看本分区**：入口改为 `?applyType=allianceManager&scope=zone&zoneId=xxx`，
  待审核与已审核都严格按 `zoneId === 本分区` 过滤；审批流程里的分区选择器锁定为只读（`.zoneLocked`）。
  超管从自己控制台进入时不带 `scope`，仍是全部分区。**区管与超管都可审批**（`auth.canReviewAllianceManager`）。
- **修「一边批准了另一边看不到」的根因**：审批落库用的分区原本取 `availableZones[applicantZoneIndex]`，
  而 `applicantZoneIndex` 是**全部分区**的下标，区管的 `availableZones` 只有自己那几个区 → 下标错位，
  拿到别的分区甚至 `undefined`，于是 `zoneId` 写错/写空 → 区管侧按分区一过滤就"看不到已批准"。
  改为直接用申请自带的分区对象 `applicantZone`（另加 `selectedZone` 兜底）。
- 新增 `applicantZonePickerIndex` = 在 `availableZones` 里的下标（选择器专用），与 `applicantZoneIndex`（全局下标）分开，不再混用。
- **缓存 key 必须带范围**：`adminReviewCache_<type>_z<zoneId>`，否则分区版与全量版列表会互相覆盖。
  任一审批操作仍会 `clearReviewCache()` 清掉所有前缀 key → 两边下次进入都重新拉取，状态一致。
- `zoneScope` 下不显示顶部统计条（服务端统计是全分区口径，与筛选后的列表对不上会误导）。

### 兵种阶级（stage）同步

  新增 `ga.pickAccount()` / `ga.specsOf()` / `ga.allianceIndexIn()`，切换账号时把该账号的
  熔炉 + 三兵营等级（**含兵种阶级**）+ 最近一次报名用的联盟一起同步过去；手动填的新昵称不动任何资料。

### 修正（重要）
- **联盟选择器高度比原来矮了 16px（占位错位的根因）**：旧 `.picker-compact` **没写 `box-sizing`**，是 content-box → 实际高 = `height:32` + 上下 `padding:8×2` = **48px**；而 `alliance-picker` 的 `.ap-field` 统一写了 `border-box`，照抄 `height:32px` 出来只有 **32px**。同排的「分区/日期/时间」框都是 48px，于是联盟框明显矮一截。
  - 实测截图：分区框 96px@2x（48px），联盟框 66px@2x（33px），差 **1.5 倍**，与推断一致。
  - 修法：`.ap-field-compact` 改 `height:48px; padding:0 12px`（border-box 下等于原视觉高度）；`.ap-field-field` 改回旧 `.picker-row` 的 `padding:9px 12px`（不设固定高）。**全项目 14 处联盟选择器一次性对齐。**
  - 顺手在 `app.wxss` 的 `.picker-compact` 上加了这条高度陷阱的注释，避免以后再踩。

### 变更
- **分区切换统一收到首页**：区管控制台、盟管控制台及其子页不再提供页内切区，分区一律用新增的全局 `.zone-readonly` 只读标签（48px 灰底、不可点）展示，尺寸与 `.picker-compact` 对齐。
  - `admin/home`（原「管理员控制台」→ 标题改为「**区管控制台**」）：移除「当前分区」选择器，改只读。
  - `admin/position-manage`（官职管理）：**超管进入也不再能选分区**（原来 showZonePicker 为 true），统一只读；无分区时显示「无分区」而不是加载中就报「无分区」（新增 `zoneLoaded` 标志）。
  - `admin/member-manage`、`admin/statistics`：同样改只读；对应 json 移除 `zone-selector` 注册，页内 `onZoneChange` 一并删除。
  - ⚠️ **保留**页内分区选择器的只有超管自己的控制台（全局统计 / 联盟管理 / 成员管理 / 用户身份管理 / 管理员审核）——那里跨分区查看是核心功能。如需一并改成只读，说一声即可。
- **盟管控制台（`auditor/home`）改版**：联盟选择器移到**顶部账号卡右侧**（账号名 / 角色 / 只读分区标签在左，联盟在右），原来是下方独立卡片里的「分区 + 联盟」两列。分区改为只读，不再可选。
  - 超管：右侧是当前分区下的全部联盟（弹窗选）；区管/盟管：本人可管理的联盟，**只有一个时直接只读展示联盟名**，不再弹一个只有一个选项的网格。
  - 进入时优先选回 `lastAllianceId`（上次选的联盟），不用每次重选。
- **超管控制台移除 4 个入口**：堡垒配置、官职管理、国战报名、兵工厂&峡谷（改由盟管/区管控制台进入，避免两套入口各改一份）。对应 `goToTimeSlotConfig` / `goToPositionManage` / `goToBattleConfig` / `goToArsenalConfig` 四个方法一并删除。
- **页面标题修正**：`admin/time-slot-config` 与 `auditor/config` 的标题由写错的「时间段配置」改为「**堡垒配置**」（页面内容本来就是堡垒名称 + 奖励标签）。

### 优化（性能）
- **分区 / 联盟不再每次回源，管理页「转圈 3-6 秒」消失**：`utils/db.js` 为 `getAllZones` / `getZonesByCreator` / `getAlliancesByZone` 加了「进程内存 + 本地 storage」双层缓存（TTL 10 分钟）：
  - 命中 → **同步返回**，页面立刻出壳（热启动读内存、冷启动读 storage，都不等网络）
  - 未命中 → 回源并回写
  - 命中但已过期 → 先用旧值，同时**后台静默回源**（stale-while-revalidate），同一 key 60 秒内只回源一次，避免连开多页打请求风暴
  - 写入类操作（建分区 / 改联盟名 / 绑盟管 / 初始化联盟 / 加区管）后自动 `invalidateMeta` 失效
  - 需要强制最新时传 `{ force: true }`
  - 实测：缓存命中 **0ms** 返回，无缓存时才会等网络（3s 模拟 → 3001ms）。
- 盟管控制台/区管控制台的联盟列表复用该缓存，不再各自写裸查询。

### 说明
- 本轮**无云函数改动**，无需重新部署。
- 新增全局样式 `.zone-readonly`（只读分区标签），各管理页统一使用，不要再写页内副本。

## v1.14.0（外部链接改「复制链接打开」）

### 背景（重要 · 结论性）
小程序后台**没有「业务域名」入口 = 本小程序是个人主体**。微信官方规定：

> 「目前小程序内嵌网页能力暂不开放给个人类型账号和小游戏账号」

即个人主体**既不能配置业务域名，也不能使用 `web-view` 组件**，后台直接不给入口；且小程序**没有唤起系统浏览器的 API**（微信刻意不开放，防止外跳）。所以「点链接直接打开网页」在这个主体下**没有任何实现路径**，只能复制地址让用户去浏览器打开。

### 变更
- **外部链接统一走 `utils/link.js` 的 `openExternal()`**：复制链接 → `hideToast()` 掐掉系统提示 → 弹「…链接已复制，请粘贴到浏览器打开」（2.5s）。
  - 功能介绍各版本 → 「V1.7.0 说明链接已复制，请粘贴到浏览器打开」
  - 官网 → 「官网链接已复制…」；备案查询 → 「备案查询链接已复制…」
- **「关于」页官网 / 备案号右侧的 `›` 箭头改成「复制」标签**：点击行为就是复制，箭头会误导用户以为能站内打开。
- **功能介绍列表页顶部提示**改为「点击版本复制说明页链接，粘贴到浏览器即可查看」。
- **`pages/common/webview` 从 `app.json` 的 `pages` 中移除**（页面文件保留）：个人主体带着打不开的 web-view 页有审核风险。
  - 🔧 将来主体升级为企业/个体工商户并配好业务域名后，恢复两步：① 把该路径加回 `app.json`；② `utils/link.js` 的 `openExternal` 换成 `navigateTo` 该页。步骤已写进两处文件头注释。

### 说明
- 本轮**无云函数改动**，无需重新部署。
- 若不想让用户体验「复制 + 切浏览器」这一步，唯一出路是**升级为企业/个体工商户主体**（需营业执照 + 认证），配好业务域名后可恢复站内直开。

## 数据库集合与权限

| 集合 | 说明 | 建议权限 |
|------|------|----------|
| `users` | 用户与角色 | 所有人可读写 |
| `superAdmins` | 超管手机号名单 | 仅创建者可读写 |
| `admins` | 区管 / 盟管 / 分区开通申请 | 所有人可读写 |
| `settings` | 全局配置（含自动清理） | 所有人可读 |
| `zones` | 分区 | 仅创建者可写，所有人可读 |
| `alliances` | 联盟 | 仅创建者可写，所有人可读 |
| `timeSlots` | 堡垒时间段 | 仅创建者可写，所有人可读 |
| `battleConfigs` / `arsenalConfigs` / `canyonConfigs` / `positionConfigs` | 各类活动配置 | 仅创建者可写，所有人可读 |
| `registrations` / `battleRegistrations` / `arsenalRegistrations` / `canyonRegistrations` / `positionRegistrations` | 各类报名记录 | 仅创建者可写，所有人可读 |
| `allianceMembers` | 联盟成员名单（跨周延续） | 通过云函数读写 |
| `allianceActivity` | 周活跃记录（仅保留本周） | 通过云函数读写 |
| `feedbacks` | 用户反馈与回复 | 通过云函数读写 |

> 联盟活跃相关读写全部收口到 `manageAllianceActivity` 云函数，绕开客户端 20 条查询上限与集合写权限限制。

## 定时清理

| 云函数 | 频率 | 职责 |
|--------|------|------|
| `clearRegistrations` | 每小时 | 按 `settings.autoClear` 清空报名数据；**每次运行都会清理联盟活跃过期周数据**（不受开关门控，跨天必须立刻清） |
| `cleanupApplications` | 每日 | 删除已处理超 14 天的审批记录（保留 pending） |

⚠️ **定时触发器按云函数独立注册，且开发者工具中不可见**，需到网页版云开发控制台确认。若触发器列表为空，函数不会自动运行——需重新部署或网页版手动添加。

## 更新版本号

修改 `miniprogram/utils/version.js` 中的 `APP_VERSION`：

```javascript
const APP_VERSION = '1.7.0'  // 更新此处
```

发版流程：改版本号 → dev 提交 → 合并 master → 推送两分支 → 打同名 tag（`v1.7.0`）。tag 号应与 `APP_VERSION` 保持一致。

## v1.7.0 (2026-09-17)

### 新增功能：联盟活跃统计

完整的成员周活跃度管理模块，替代群里人工点名。

- **数据双层设计**
  - `allianceMembers` —— 持久成员名单，跨周延续
  - `allianceActivity` —— 周活跃记录（`weekStart` + `activeDays[7]`），仅保留本周
- **云函数 `manageAllianceActivity`**（服务端权限，绕开客户端 20 条查询上限）
  - actions：`listMembers` / `getZoneOverview` / `setActive` / `addMember` / `removeMember` / `joinByRegistration` / `markSelfActive` / `cleanupExpired`
- **成员详情页**（`pages/auditor/alliance-activity`，盟管与区管共用）
  - 顶部「今日活跃成员 X/Y」+【添加】【保存截图】同一行
  - 今日活跃 / 未活跃双列表，2–3 列自适应，勾选与删除互相迁移
  - 长按成员行可删除，二次确认文案：「确认删除当前用户本周活跃信息，用户下次登录小程序仍可自动添加」
  - 保存截图：8 列表格（成员 + 本周 7 天），活跃打勾、未活跃打叉，未来日期留空
- **区管总览页**（`pages/admin/alliance-activity`）
  - 8 列表格，第一列【联盟】固定，后 7 列为日期与活跃人数
  - 列宽自适应，常见机型一屏看全 7 天；点联盟名下钻到该联盟管理
  - 成员为 0 的联盟不展示
- **自动活跃登记**
  - 用户打开小程序即自动标记当日活跃，无需管理层操作
  - 联盟归属三级兜底：`users.allianceId` → 本地最后一次选择 → 回溯报名记录
  - 均带分区校验，防止多区账号串区；跨天自动重新上报
  - 报名成功后立即标记活跃，团队长可即时看到

### 优化

- 区管控制台禁止页内切区：联盟配置移除顶部「选择分区」（改为只读标签），堡垒配置分区改为置灰只读文本
- 「我的报名」独立成页（`pages/user/my-records`），原「我的」页改为纯个人中心
- 板块标题统一为强标题样式（渐变色强调条 + 加粗 + 条数）

### Bug 修复

- **保存截图日期列看不见**：`0916(三)` 单行在窄列被截断成 `091…`。表头改为两行（第一行 `0917`、第二行 `周四`），截图与页面表头同步调整
- **老用户未被自动登记**：`lastAllianceId` 只存本地且不上报，`users.allianceId` 仅报名成功才回写 → 老用户为空。改为三级兜底解析归属，并回写 `users`
- **自动登记被节流吃掉**：`onLaunch` 时 `currentZone` 尚未恢复 → 上报失败 → 锁 60 秒 → 分区就绪后的补报被挡掉，一次都没成功。改为 `force` 参数绕过节流
- **区管页显示「无分区」**：`onLoad` 用 URL 传 `zoneId` 时未设 `zoneName`。改为移除整个分区卡片
- **总览页日期列滚动错位**：固定 `scrollLeft=(dayIndex-2)*56` 在今天已可见时仍会滚动，把周一挤出视野。改为实测宽度，仅在溢出时滚动
- **我的报名缓存永不命中**：读用 `'myregs_'+uid+'_'+zoneId`、写用 `'myregs_'+uid+(zoneId?'_'+zoneId:'')`，无分区时拼接不一致。统一走 `cacheKey(userId, zoneId)`

## v1.6.4 (2026-08-19)

### Bug 修复：超管审批页

- **待审记录看不到**：客户端 `get()` 有 20 条硬上限且静默截断。列表改为走 `manageAdmin` 云函数服务端全量拉取并补全昵称
- **删了又复活**：`admins` 集合为「仅创建者可写」，超管非创建者时前端 `remove` 被拒且静默失败。删除改为服务端 `remove` + `superAdmin` 鉴权
- **加载超过 10 秒**：云函数冷启动 + 5 个 `count()` 串行。改为 storage 缓存优先渲染 + 单次 `callFunction` + stats 内存统计
- 区管 / 盟管 / 分区开通三类的 `valid` 隐藏 bug：去掉 `wx:if` 对 `item.valid` 的依赖，昵称查不到回退「未知用户」

### 新增功能

- 云函数 `cleanupApplications`：每日定时删除 `admins` 中已处理（approved/rejected）超 14 天的记录，**绝不删 pending**。`RETENTION_DAYS` 可调

## 数据库集合与权限

| 集合 | 说明 | 建议权限 |
|------|------|----------|
| `users` | 用户与角色 | 所有人可读写 |
| `superAdmins` | 超管手机号名单 | 仅创建者可读写 |
| `admins` | 区管 / 盟管 / 分区开通申请 | 所有人可读写 |
| `settings` | 全局配置（含自动清理） | 所有人可读 |
| `zones` | 分区 | 仅创建者可写，所有人可读 |
| `alliances` | 联盟 | 仅创建者可写，所有人可读 |
| `timeSlots` | 堡垒时间段 | 仅创建者可写，所有人可读 |
| `battleConfigs` / `arsenalConfigs` / `canyonConfigs` / `positionConfigs` | 各类活动配置 | 仅创建者可写，所有人可读 |
| `registrations` / `battleRegistrations` / `arsenalRegistrations` / `canyonRegistrations` / `positionRegistrations` | 各类报名记录 | 仅创建者可写，所有人可读 |
| `allianceMembers` | 联盟成员名单（跨周延续） | 通过云函数读写 |
| `allianceActivity` | 周活跃记录（仅保留本周） | 通过云函数读写 |
| `feedbacks` | 用户反馈与回复 | 通过云函数读写 |

> 联盟活跃相关读写全部收口到 `manageAllianceActivity` 云函数，绕开客户端 20 条查询上限与集合写权限限制。

## 定时清理

| 云函数 | 频率 | 职责 |
|--------|------|------|
| `clearRegistrations` | 每小时 | 按 `settings.autoClear` 清空报名数据；**每次运行都会清理联盟活跃过期周数据**（不受开关门控，跨天必须立刻清） |
| `cleanupApplications` | 每日 | 删除已处理超 14 天的审批记录（保留 pending） |

⚠️ **定时触发器按云函数独立注册，且开发者工具中不可见**，需到网页版云开发控制台确认。若触发器列表为空，函数不会自动运行——需重新部署或网页版手动添加。

## 更新版本号

修改 `miniprogram/utils/version.js` 中的 `APP_VERSION`：

```javascript
const APP_VERSION = '1.7.0'  // 更新此处
```

发版流程：改版本号 → dev 提交 → 合并 master → 推送两分支 → 打同名 tag（`v1.7.0`）。tag 号应与 `APP_VERSION` 保持一致。
